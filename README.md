## 🎯 Overview & Product Vision

Leadership and operations executives at drone technology enterprises like Skylark require rapid, verified visibility across sales and delivery operations:
* *"Give me an executive leadership update."*
* *"Are we executing work orders on deals that haven't actually been won yet?"*
* *"What is our contract value variance between sales CRM commitments and delivery bookings?"*
* *"What is our gross vs. net accounts receivable position, taking client credit balances into account?"*

Answering these questions across disparate Monday.com boards typically requires tedious spreadsheet exports, ad-hoc python scripts, and subjective guesswork.

### Architectural Principles
1. **The LLM is Strictly an Orchestrator**: The LLM is not used as the source of truth for business arithmetic. User intent and conversational synthesis are handled by the LLM, while business metrics, KPI values, risk counts, and evidence metadata are generated by deterministic Python analytics from normalized source data. The read-only MCP server layer acts as the structured integration boundary.
2. **Deterministic Analytics**: Business metrics are calculated by typed Python analytics functions rather than by the LLM. Every total, percentage, weighted pipeline calculation, credit balance reconciliation, and cross-board variance is calculated strictly in typed Python analytics engines. Structured analytical responses (KPI cards, risk flags, evidence metadata) are generated deterministically before LLM narrative synthesis.
3. **Enterprise Data Resilience**: Normalizes 71 free-text PO quantity units, preserves negative accounting credit balances, extracts Excel serial epochs, and isolates 4 orthogonal status dimensions before anything reaches the business layer.
4. **Transparent Governance Caveats**: Distinguishes unbilled/uncollected (`null`) from zero (`₹0`), highlights unrecorded deal values (52% null in raw deals), and quantifies live cross-board linkage coverage.

```json
    },
    {
      "label": "Current Outstanding Receivables",

      "detail": "{NEGATIVE_BILLING_COUNT} work order(s) show negative amount-to-be-billed totaling {NEGATIVE_BILLING_TOTAL} Excl GST.",
      "severity": "medium"
    }
  ],
  "evidence": {
    "sources": ["Work Orders"],
    "records_analyzed": "{WORK_ORDER_COUNT}",
    "data_coverage": "100% of tracked work orders",
    "calculation": "deterministic revenue aggregation via compute_revenue_summary"
  },
  "caveats": [
    "{CREDIT_ACCOUNT_COUNT} credit balance accounts offset net receivables by {CREDIT_TOTAL_FORMATTED}.",
    "{NEGATIVE_BILLING_COUNT} line items contain negative billing totalling {NEGATIVE_BILLING_TOTAL_FORMATTED}."
  ],
  "follow_ups": [
    "Break down receivables by customer credit accounts",
    "Are we executing work orders on deals that haven't been won yet?",
    "Give me an executive leadership update"
  ]
}
```

### Deterministic Structured Guarantees:
* **KPI Values & Risk Indicators**: Generated by deterministic Python analytics functions; the LLM cannot alter or hallucinate metric values in `kpis`, `risks`, or `evidence`.
* **Evidence & Provenance Metadata**: Exposes the source board(s), record count analyzed, data coverage notes, and the underlying calculation function.
* **Separation of Concerns**: The LLM synthesizes natural-language markdown for the response body, but internal reasoning or chain-of-thought is never exposed to the user.
* **Resilient Fallbacks**: If `structured` is null (e.g. clarification turns, non-analytical greetings, or legacy responses), the frontend renders standard markdown body and caveat banners without errors.
* **Monday API Errors**: If Monday.com is unreachable, the system raises a controlled `MondayAPIError` and returns a transparent service notice (`{"error": "Monday.com data is temporarily unavailable. No fabricated or stale business values were used."}`); no fabricated KPI cards or evidence blocks are emitted.

## ⚡ Core Capabilities & Technical Highlights

### 1. Cross-Board Intelligence (Deals ↔ Work Orders)
Monday.com's native `Connect Boards` column (`Linked Deal`) links projects between the Deals and Work Orders boards.
> **Cross-Board Ground Truth**: Cross-board analytics only treats confirmed native Monday Connect Board relationships as confirmed links. Unmatched records are not silently inferred as linked.
* **Confirmed Linkage**: Exactly **15 of 176 Work Orders (8.5%)** have confirmed relations to Deals on Monday.com across **344 valid Deals**.
* **Commercial Risk on Unclosed Deals**: Identifies work orders being actively executed or completed for proposals that are still `Open`, `On Hold`, or `Dead`.
  * *Audit Result*: Discovered **5 work orders** totaling **₹20,838,860.24 Excl GST** linked to unclosed deals, including project `SDPLDEAL-099` (Ongoing, ₹14.39M) linked to an Open proposal (`Goku`).
* **Contract Value Leakage & Variance**: Compares CRM Deal Value against Work Order Booked Amount and Billed Revenue.
  * *Audit Result*: Discovered **6 projects with contract leakage** totaling **₹114,710,914.13**, where booked scope exceeded contracted CRM deal value.
* **Won Deals Backlog**: Identifies Closed-Won deals that have not yet had a corresponding delivery work order spun up.
  * *Audit Result*: **96 out of 103 Won Deals** have zero linked work orders on Monday.com, representing **₹101,899,594.90** in unbooked pipeline backlog.
* **Unlinked Execution Financial Exposure**: Detects work orders without CRM attribution (**161 orders** totaling **₹180M+** in booked volume).
* **Delivery View Alignment Matrix**: An interactive UI table in the web dashboard displaying linked deal names, stages, contract values, work order execution status, booked amounts, and automated risk badges.

### 2. Deterministic Business-Metric Computation
The reasoning LLM never computes arithmetic internally. It dispatches typed queries to dedicated analytical tools backed by the normalized data layer and read-only MCP server:
* `get_pipeline_summary`: Unweighted vs. probability-weighted pipeline, stage distribution, sector breakdowns.
* `get_revenue_summary`: Bookings, billed revenue (Excl/Incl GST), collections, gross receivables, and net receivables.
* `get_cross_board_delivery`: Alignment between Work Orders and Deals via native Monday Connect Boards (`view="summary" | "unclosed_deal_risk" | "value_variance" | "won_without_wo" | "alignment"`).
* `get_leadership_update`: Automated executive briefing combining revenue, delivery health, pipeline velocity, and audit risks.
* `get_data_quality_report`: Dynamic data-quality metrics, null rates, GST tolerance checks, and bookkeeping flags.

### 3. Real-World Dirty Data Resilience
* **71 Free-Text PO Quantity Formats**: Extracts numeric values and standardizes units across `HA`, `Acres`, `KM`, `RKM`, `MW`, `towers`, `days`, `months`, `images`, `sites`, `mines`, while classifying non-numeric lump-sum entries (`L/s`, `Rate based on MW slabs`).
* **Preservation of Legitimate Negative Balances**:
  * **11 Customer Credit Accounts** (negative `Amount Receivable`, min −₹160.24) representing client overpayments and credit balances—never clamped to zero. Both gross and net receivables are reported.
  * **6 Negative Billing Adjustments** in `Amount to be billed` representing execution volume scope adjustments.
  * **2 Negative Balance Quantities** where executed volume exceeded estimates.
* **Blank ≠ Zero Accounting**: Missing monetary fields are tracked as `null` (unbilled / uncollected), preventing margin distortions.
* **4 Orthogonal Status Dimensions**: Separates `Execution Status` (fulfillment), `Invoice Status` (billing), `WO Status (billed)` (ERP account closure), and `Billing Status` (exception handling).
* **GST 18% Mathematical Tolerance**: Reconciles `Incl ≈ Excl * 1.18` within a ±₹0.50 margin across 175 rows.
* **Header Deduplication & Phantom-Sum Suppression**: Eliminates embedded header rows (rows 52 and 181 in Deals, yielding exactly 344 valid deal records) and drops phantom summary/total rows.

### 4. Read-Only MCP Integration Layer
* Built using the official Python `mcp` SDK, registering **exactly 3 public MCP tools**:
  1. `get_work_orders`: Fetches all Work Orders with mapped column titles and resolved Connect Board links.
  2. `get_deals`: Fetches all Deals with mapped column titles and header contamination filtered.
  3. `get_schema`: Introspects column titles, IDs, and types for a given board.
  *(Note: `get_board_schema` is retained strictly as a Python compatibility alias; it is not registered as a fourth MCP tool).*
* **Read-Only Resources**: Exposes `monday://work_orders`, `monday://deals`, and `monday://schema/{board_type}`.
* **Mutation Protection**: Code-level regex barriers reject any `mutation` operation **prior to network transmission**.
* **Cursor Pagination**: Robust cursor-based iteration fetches high-volume boards without hitting complexity budgets.
* **Thread-Safe TTL Cache**: In-memory 5-minute TTL cache prevents excessive upstream API calls during high-frequency analytical queries.

### 5. Deterministic Clarification Engine
Queries with ambiguous parameters trigger clarifying questions with interactive selection chips:
* **Time Boundary Ambiguity**: When asked about *"this quarter"*, prompts whether to evaluate against **Indian Fiscal Year (Q4 FY25-26: Jan–Mar)**, **Calendar Year (Q1: Jan–Mar)**, or **All-Time**.
* **Vague Horizon Ambiguity**: Prompts like *"recently"* or *"past few months"* request specific date windows.
* **Sector Aliasing**: Automatically maps terms like *"energy"* or *"solar"* to the board's standard `"Renewables"` sector.

## 📊 Monday.com Board Configuration

To replicate or connect your Monday.com workspace:

1. **Work Orders Board**:
   * Create a board named `Work Orders`.
   * Import `Work_Order_Tracker Data.xlsx` (Row 1 is empty; configure Row 2 as column headers).
   * Ensure `Amount in Rupees (Excl of GST)`, `Billed Value`, and `Amount Receivable` are mapped to **Numbers** columns.
   * Ensure `Execution Status`, `Invoice Status`, and `Sector` are mapped to **Status / Dropdown** columns.
2. **Deals Board**:
   * Create a board named `Deals`.
   * Import `Deal funnel Data.xlsx` (Ensure rows 52 and 181 are removed as repeated header rows).
   * Map `Masked Deal value` to a **Numbers** column.
   * Map `Deal Stage`, `Deal Status`, and `Closure Probability` to **Status / Dropdown** columns.
3. **Cross-Board Connect Boards Column**:
   * On the `Work Orders` board, add a **Connect Boards** column named `Linked Deal`.
   * Connect it to the `Deals` board to enable live cross-board relation queries.

For exact column IDs and schema specifications, see [`scripts/monday_board_setup.md`](scripts/monday_board_setup.md).
